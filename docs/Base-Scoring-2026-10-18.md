## 核对结果与本轮边界

基础规则书印刷 p10 的收尾顺序是：结算收尾阶段效果、复位城市样式标记、顺时针传递起始玩家标记、推进回合标记；8 回合后结算最终分数。角色/城市样式中存在收尾效果及玩家选择。当前项目未录入这些牌和相应标记状态，不能把“采集完成”直接当成“完整收尾完成”，也不能默认其效果为零。

本轮实现**区块控制和基础计分的只读计算**，供规则验证和未来完整结算复用。没有新增正式收尾、终局执行、角色/样式状态或胜利状态；没有自动换回合、转换库存或累加玩家权威分数。状态格式继续为既有 1.0.0–1.5.0，项目版本仍为 0.2.0，Accepted ADR-0001 决策不变。

依据：已提供的《游城拓荒铸基者-规则书20230803.pdf》，SHA-256 `6b87c026e317606de2324276ff117480b8e104f5b925a21d43b95af176ddbf42`；已视觉核对 p10 分数结算、p12 区块控制、p23 两人规则。地图区块归属与分值继续使用已核验定义和 Map-Analysis v0.1.0 的 M16/M17，不从坐标或航道端点推断。

## 区块控制

`getRegionControl(position, definition)` 返回各区块的真实影响力明细、领先者及唯一控制者。

| 来源 | 计数与归属 |
| --- | --- |
| 资源点影响力标记 | 每枚 1，归资源点定义的 regionId |
| 航道影响力标记 | 每枚 1，归航道定义的 regionId；三/四端不复制计数 |
| 城市 | 所在资源点区块额外 +2，不占槽，不消耗玩家标记 |
| 供应/计分标记、余额与已得分 | 不构成区块影响力 |

最多且唯一的玩家获得控制权；正数并列无人获得，空区块也无人获得。查询约定空区块的 leadingPlayerIds 为 []，正数并列时列出并列者；controllerPlayerId 均为 null。奖励分取自地图定义：E/F 各 4，其他存在区块各 3；两/三人图 7 区共 23，四人图 8 区共 26。R 灰区只有航道，不因端点属于 A–F/G 而改变计分区块。

控制者与累计控制影响力均是派生查询，不保存第二份权威控制表。即使区块中有城市，也继续按实际槽位标记和城市 +2 比较，不把城市视为自动占领。

## 剩余资源换分

`getResourceScoreBreakdown(balances)` 只返回换分明细和未成组余数，不扣除资源。每种资源单独取完整组，不合并余数，不四舍五入。

| 资源 | 每 1 分需要数量 |
| --- | ---: |
| 至纯源石 pure-originium | 1 |
| 异铁 iron | 6 |
| 源石 originium | 8 |
| 源岩 orirock | 9 |
| 哥伦比亚金券 columbia-voucher | 不直接计分，参与同分判定 |

例：19 源岩、17 源石、13 异铁、3 至纯源石共 9 分，普通资源各余 1；金券不增加分数。使用 BigInt 进行内部整除与求和，输出为可 JSON 保存的安全整数；汇总超出安全整数则抛出 ScoringError/SCORE_OVERFLOW，不静默舍入。

## 基础总分与同分比较

`getBaseScoringPreview(position, definition)` 返回：

- scope 固定为 `base-components-only`；各玩家 existingPoints（当前 score）、regionPoints、resources 和 totalPoints，以及区块明细。
- leadingPlayerIds 是**给定局面、已实现基础分项中的领先者**，不是已经宣告的正式赢家。
- 先比较总分，再按剩余金券、剩余至纯源石依次比较；仍相同则保留全部并列者。resolvedBy 表示 score / columbia-voucher / pure-originium / shared。

至纯源石先按数量贡献分数，若总分/金券相同仍按实际持有数量用于第二次比较；预览不消耗资源。普通资源余数、玩家顺序、颜色和供应标记数都不是额外平局规则。两人局初始非起始玩家的 3 分已经在现有 score 中，不能遗漏或再加一次。

```typescript
import { getGamePosition, getBaseScoringPreview } from '@nomad-city-online/game-core/game';

const position = getGamePosition(state, definition);
const preview = getBaseScoringPreview(position, definition);
// 不把 preview 当成客户端提供的权威分数；不据此跳过角色/样式收尾效果。
```

输入必须是通过现有共享局面校验的 GamePosition；完整 GameState 用 getGamePosition 提取，保留单一权威事实。调用会验证定义/摘要、标记归属和守恒、城市及资源引用，拒绝伪造控制缓存等额外字段。返回结果深度冻结，输入不变；重复查询不会重复发分。
