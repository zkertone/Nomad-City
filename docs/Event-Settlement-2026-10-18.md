## 接口与信任边界

源码均位于 `packages/game-core/src/game/`，通过根包或 `/game` 导出。

- `GamePosition` / `gamePositionSchema`：抽取既有 GameState 中 `gameId`、`board`、`players`、`markerSupplyByPlayer` 的共同字段，不增加另一份持久化局面、账本或阶段。
- `validateGamePosition` / `parseGamePosition`：复用原有地图/目录引用、精确玩家覆盖、资源标记数据、库存所有权和逐枚守恒校验；不核验回合许可或完整历史。
- `getGamePosition(state, definition)`：先验证完整 GameState（包含入场进度约束），再产生冻结工作视图。
- `getEventChoiceRequirements(position, definition, context, choiceId)`：返回是否要求费用决定、余额能否支付和当前合法放置槽；结果不等于行动许可。
- `settleEventChoice(position, definition, context, payload)`：返回冻结的 `{position, receipt}`；不修改或冻结调用者输入。receipt 是本次计算结果说明，不是第二套权威状态或完整事件历史。

可信调用方提供 context：`{gameId, actorId, nodeId, cardId}`。调用前必须确定当前轮到谁、为何揭示这张牌，以及该事件尚未结算。核心另外核对对局/玩家存在、事件牌与节点上实际揭示的资源标记一致，阻止上下文引用串用；这些检查不替代身份认证和行动授权。

玩家选择只接受严格字段：

```typescript
{ choiceId: 'Y05:1', costDecision: 'pay', influenceSlotId: '...' }
```

`costDecision` 仅在有前置费用时出现且必须明确；没有费用时不能附带该决定。没有放置效果的选项不能附带目标字段；无法放置时可省略目标或传 null；有合法目标时须明确选中该范围内的一个空槽。拒绝额外 actorId、cardId、奖励金额等字段。条件选择 decline 时不扣款、不放置，不能同时夹带实际放置目标。

## 无法执行与错误

规则内的无法放置会生成 `skipped`，原因区分 `no-supply` / `no-legal-slot`，并保留此前收益/费用。非法请求（例如越范围目标、缺少必要选择、伪造牌引用或不足额支付）抛出错误，不产生新局面。数值溢出属于存储表示错误，拒绝整次计算且保留原输入；不会夹限、舍入或把它当作合法规则中的奖励放弃/退款。

纯函数对同一输入可重复计算，因此自身没有持久化幂等或防重放能力；调用方必须原子验证待结算事件和状态版本，并只应用一次。当前只有入场调用方已具备单进程预期版本检查，仍没有数据库 CAS、认证网关、公开状态投影或跨进程事务。
