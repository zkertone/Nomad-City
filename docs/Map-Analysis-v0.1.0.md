## 2. 地图不是方格移动棋盘

资源点是移动城市的停靠地点；航道是连接资源点的独立区域。资源点和航道都有影响力空格，也都归属控制区块。没有依据将地图建成六角格、规则方格、按几何距离移动的棋盘，或加入障碍区、运输区等额外地形。

同一航道区域存在分叉并连接超过两个资源点，不能强制将一条航道建成只有两个端点的普通边。建议建模为“资源点—航道—资源点”的关联图，航道保留唯一身份、影响力空格和区块归属。拓扑已从实物核对；采用该模型的 ADR 仍为待确认提案。

**部署/调度不使用路径距离。** p05–06 仅规定影响力放置及目标空格限制；调度没有“相邻一格”或“沿航道逐格”要求。探索和采集才计算航道连接及路费；城市移动另有直接航道连接要求。

## 6. 必须避免的错误规则

1. 将调度限制为邻接移动，或让部署/调度支付路费。
2. 将“城市移动经一条航道”理解为只能去编号相邻点，或按相机距离算一步。
3. 将区块当成一个资源点，或将区块控制视为城市独占所有权。
4. 将未探索点的资源类型写死；将事件颜色等同于区块颜色。
5. 将红区封锁扩大为红区航道禁用，或据图中“4 回合”将开放条件错写为第 5 回合。
6. 让资源点的城市占用影响航道槽，或让自己的城市阻止自己放置影响力。
7. 按影响力数量、影响力槽数或线段数收费；将同一采集连接里的同一航道重复收费。
8. 城市移动清除自己的影响力，漏清目标点的对手影响力，或漏归还标记。
9. 城市贡献的 2 点控制影响力占用实际影响力槽。
10. 将默认企业扩展角色效果或公路规则混入无企业扩展的基础版。
