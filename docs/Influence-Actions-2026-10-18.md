# 部署与调度 · 2026-10-18

已实现基础版两种主要行动：部署把本人供应中的一枚现存标记放到合法空槽；调度逐次移动本人棋盘上的影响力，至多两次。核心仍与 UI、网络和数据库分离，实际全局回合/角色/行动额度由未来可信调用方授权。

## 规则依据

本轮先读取最新源码、DevLog、Accepted ADR-0001，视觉核对基础规则书 p05 部署和 p06 调度；沿用已核对的 p13 执行顺序/尽量执行约束。没有修改官方规则、地图、牌数据或架构决策。

| 行为 | 实现与限制 |
| --- | --- |
| 部署 1 次 | 从本人供应取 1 枚，选一个合法空槽；不能指定任意标记 ID 或执行第二次 |
| 调度至多 2 次 | 每次选本人棋盘影响力及一个合法空槽；可以零次/一次后结束，两次后自动完成 |
| 同一标记 | 没有添加“必须移动不同标记”的限制；同一标记可以连续移动两次，也可以移回刚腾空的源槽，两次均计数 |
| 空槽与资源点 | 航道空槽可选；资源点须已探索且没有其他玩家城市；本人城市允许 |
| 距离与路费 | 不要求相邻、不需要连接路径，不支付路费；不能套用探索距离或红区航道封锁 |
| 真实供给 | 部署须有本人供应；调度复用原棋盘标记，因此供应为零仍可调度 |
| 无法执行 | 无合法目标/没有可移动标记时自动完成，计 0 次；不创造标记、不收费用 |
| 不放弃可执行的部署 | 部署没有人为跳过一个可执行的非条件操作的请求；调度有“至多”的明确许可，可提前结束 |

两种行动不揭示事件、不收获资源、不移动城市、不清除其他玩家的影响力。当前实现普通行动；角色/城市样式的额外次数或特殊条件尚未接入。

## 接口

代码：`packages/game-core/src/game/influence-actions.ts`、`influence-action-invariants.ts`。公共函数从根包或 `/game` 导出。

- `openDeploymentWindow` / `openDispatchWindow`：可信单次主要行动授权，参数与现有窗口一致：actorId、roundNumber、expectedVersion，以及仅首次初始化时可提供的服务端 deckOrder。完整回合、角色阶段、顺时针轮流和额度仍由未来调用方检查，不能把这些函数开放成玩家请求。
- `getDeploymentSlotIds`：查询本次部署合法槽。
- `getDispatchSourceSlotIds` / `getDispatchTargetSlotIds`：查询当前可移动的本人棋盘标记及目标，不接受计分标记或供应标记作为源。
- `applyInfluenceCommand(state, definition, {authenticatedPlayerId}, payload)`：验证对局/身份/预期版本/种类/阶段，解析副本执行并冻结结果。

| 玩家 type | 除 gameId / expectedVersion 外允许的字段 |
| --- | --- |
| deploy-influence | slotId |
| dispatch-influence | sourceSlotId、targetSlotId |
| finish-dispatch | 无额外字段 |

请求不接受 actorId、回合、费用、路径、标记 ID、数量或自行填写的次数。源/目标不能相同，目标必须当时为空；不能占用对手标记或自己占用的槽。可读查询对错误玩家/阶段/源返回空数组，不返回可绕过步骤的权限。

## 逐次处理与恢复

调度第一步后仍保留待选状态和 `operationsCompleted: 1`，因此可以 JSON 序列化、恢复后选第二步或结束。第二步按最新槽位验证：第一次腾出的源槽可以重新成为合法目标，第一次移入的槽不能被另一枚标记覆盖。

每次移动保留同一个 markerId/所有者，直接从源槽转移到目标，不经过供应堆，不影响计分标记或资源。第二步请求失败不撤销第一步，也不增加计数；过期版本拒绝。两步已用完后不能再移动或 finish；只有可信调用方才能授予下一行动。

内部空目标检查已分为“不考虑供给的空槽”和“需要本人供给的放置”，供部署、事件/末尾放置、调度正确复用；这修正了复用放置查询时会错误排除零库存调度的风险，不修改其原有放置规则。

## 状态与兼容

首次授权部署/调度明确使用 GameState **1.4.0**，保存唯一 `influenceAction`：kind、actorId、roundNumber、status、operationsCompleted。部署最多 1，调度最多 2，ready 状态必须仍有可执行选择。已结束行动不会再接受同类玩家请求。

1.4.0 同时支持后续探索/城市移动，切换时只保存当前一种进度，不降级格式，沿用同一 eventDecks、playerOrder、棋盘、玩家、供应和全局 stateVersion。旧 1.0.0–1.3.0 行为继续兼容，解析不自动迁移。GameDefinition、地图/事件版本与内容摘要、项目 0.2.0、已确认文案和依赖均不变。

计数仅是当前执行进度，不是第二份权威标记账本；快照校验检查结构和跨对象一致性，不能证明完整行动历史或防止不可信快照伪造。当前没有客户端整份状态入口。
