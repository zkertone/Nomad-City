## 启动与身份

使用最新main，在现有仓库根目录运行：

```bash
npm ci
npm run dev:local
```

在本机两个独立窗口打开`http://127.0.0.1:5173`，分别选择测试用户1和2。若复制了已有标签页，先退出复制页的原身份再选择测试用户2，核对两个窗口的用户和本人席位。创建新大厅即可，不必删除旧存档；此模式使用本地测试身份，未部署到真实服务器。基础环境和恢复说明见[Local-Run](../Local-Run.md)。

## 整局流程

每回合有两轮玩家行动；双人八回合共32个玩家行动轮。费用、目标、次数与时机以原规则及服务器预览为准，不为完成清单改写局面或牌序。步骤允许记录“未覆盖”，不能用猜测填通过。

| 步骤 | 两个窗口操作与核对内容 | 人工结果 |
| --- | --- | --- |
| 大厅 | 用户1创建双人大厅，用户2通过实际邀请加入；房主明确先手／顺序，双方准备后开局 | 待执行 |
| 起点／事件 | 当前玩家的顶部指引写明本人操作，另一窗口明确等待；选择实际可用起点、绿色事件及适用的入场奖励 | 待执行 |
| 回合准备 | 双人按实际顺序移除供应设施，补牌后两人可独立盖放，无须按席位顺序；另一窗口看不到本人暗置角色 | 待执行 |
| 第一回合角色 | 可以分别盖放德克萨斯和极境；按实际策略选择循环供应／最少资源，预览通过才确认；核对金券／资源只改变一次 | 待执行 |
| 建设 | 若供应有实际付得起的设施，选付款方式和空格建设，核对费用、设施和入场收益。否则记未覆盖，选择另一合法主要行动 | 待执行 |
| 入场／旅行续接 | 遇到仓库、免费移城、已揭事件、末尾影响力或追加建设时，指引应说明当前子步骤，完成前不能结束父行动 | 待执行／未覆盖 |
| 部署／调度 | 选择合法槽位；调度先来源后目标，不再移动时明确结束调度，再明确结束玩家行动轮 | 待执行 |
| 角色／样式窗口 | 普通行动结束后仍有可用角色或宣告时，先按需操作再结束；实际设施匹配时才宣告，无法匹配记未覆盖 | 待执行／未覆盖 |
| 同时采集 | 两个窗口都能编辑本人方案；选择实际资源点／连接航道，按收费航道要求选择收款人，核对预览再提交 | 待执行 |
| 修改已提交方案 | 一人先提交、另一人暂不提交；前者修改并确认替换，核对其他人的方案不显示、尚未发生实际收益 | 待执行 |
| 空采集方案 | 在任一尚未齐备的采集阶段，清空草稿后明确提交；清空按钮本身不发送方案 | 待执行 |
| 继续八回合 | 每次主要行动及其子步骤完整结束；后续角色只从本人实际可用手牌选择，不强行重复盖放已弃角色 | 待执行 |

## 操作反馈与恢复

- [ ] 按“前往操作区”能跳到当前准备或决策面板；窄屏仍能找到它，不必滚动全部槽位。
- [ ] 未揭示资源和实际资源种类／数量容易区分；同点有多座城时显示全部实际城邦。
- [ ] 指令确认后显示“已保存”；主要行动完成、样式子行动完成和结束玩家行动轮三个步骤不会混淆。
- [ ] 等待期间按钮禁用，快速连续点击不会多发另一条操作；不会把第二个点击排队为后续自动行动。
- [ ] 如出现“未收到确认”，先同步核对保存结果，不反复提交；超时不自动重试。
- [ ] 如出现“已保存，但后续选项未能同步”，同步后继续，原操作只计一次。
- [ ] 刷新后恢复已确认的入场／事件／建设子进度或本人采集方案；未确认草稿可以丢弃。
- [ ] 服务重启期间显示断线，恢复后仍是本人席位；其他人的暗牌、方案或会话不串入。
- [ ] 错误提示、长航道列表、资源分表格和键盘操作在常用窗口尺寸下可理解、可访问。

出现供应无法补齐等既有规则待确认阻塞时，记录实际局面，不自行补牌或改规则后标通过。网络异常和特殊卡型未实际遇到时标“未覆盖”；不要为了模拟错误修改生产数据库。服务端不受浏览器影响的自动恢复覆盖另见[验证记录](../testing/play-guide-validation-2026-10-28.md)。

## 问题记录格式

每条问题记录：main提交号、玩家数、本人席位、回合／阶段、操作顺序、预期、实际、同步后是否恢复、是否重复扣费／收益。最后分别统计通过、失败、未覆盖，失败项修复后复测；先完成双人流程，再重复三人／四人的同时采集和等待场景。
