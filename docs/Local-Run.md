# 本地运行与验收

目前有两条本地路径：**React可点击大厅／入场／回合准备／部署与调度**，以及**服务端大厅到八回合终局的自动验收**。其余主要行动／采集／清理／终局操作和2.5D棋盘仍待接入；自动验收不能冒充人工操作整局通过。

## 打开本地页面

仓库根目录执行：

```bash
npm ci
npm run dev:local
```

构建完成后，在自己的电脑打开`http://127.0.0.1:5173`。分窗口选择不同“本地测试身份”，由一人创建大厅、分享编号与邀请凭证，其余人加入；房主在满员后确认先手／顺时针顺序，全员分别准备，房主开始，各人点击进入对局。

当前页面可以选择合法起点、适用的B-01奖励、绿色事件选项及两人额外影响力／放弃。完成入场后，二人局按顺序移除供应设施并立即补牌，之后所有人数分别从本人角色中选择盖放；其他人只能看到盖放进度。全员盖放后，当前玩家可选择部署或调度。部署时从左侧槽位概览选目标并确认；调度时先选本人影响力来源，再选空槽目标，确认后可继续第二次或提前结束。尚无实际步骤时可以取消行动准备，已经完成的操作不能取消。主要行动完成后仍需本人点击“确认结束我的行动轮”交给下一人；此处会放弃此时可选的角色／样式机会，其操作入口尚待接入。探索／移城／建设、角色效果、采集等页面继续后续接入。页面没有正式账号注册或登录，本地身份选择器仅供开发验证。

Ctrl+C关闭应用；测试数据库保存在忽略的`.local/database`，重新启动后可用当前标签页原会话恢复，过期则重新选择身份。邀请只留在当前房主内存中，刷新后可生成新邀请。默认只监听127.0.0.1，未连接用户服务器或部署。

## 环境与命令

需要Node.js >=22.12.0、npm >=10。在仓库根目录执行：

```bash
npm ci
npm run verify
npm run check:local-web
npm run check:lobbies
```

已经按锁文件安装过依赖时可以省略npm ci。verify执行严格类型检查、全部Vitest及规则／服务／前端三包构建。check:local-web检查构建后HTTP资源、本地身份边界、3种人数入场／回合准备、首轮全员部署及第二轮调度中途重启恢复；check:lobbies再从编译包运行八回合端到端验收。根据电脑速度可能需要数分钟，后者最后应出现包含`"check":"PASS"`和`"viaLobbies":true`的JSON。

这些自动验收命令使用临时PGlite文件数据库，只监听127.0.0.1随机端口，无需配置数据库、域名、服务器或Docker。结束后关闭客户端／Nest／数据库并删除本次临时数据；不修改dev:local保留的对局或连接真实服务器。

PGlite仅为测试用WASM PostgreSQL，生产服务仍按原方案使用原生PostgreSQL。原生数据库网络、跨进程竞争及部署属于后续验收，本命令不能代替它们。

## 本地覆盖的路径

可信测试服务为不同用户签发会话，客户端经真实loopback Socket.IO完成建房、邀请加入、配置先手／顺时针、本人准备、房主开始。房间满员并全部准备后，先关闭并重开应用及本地文件数据库，确认成员／配置／准备状态恢复，再开始同一个对局。

二人、三人、四人各实际进行八回合，保留采集方案、雷蛇本人清理和正式终局计分；中间阶段由服务端原有调度器推进，检查脚本不手动调用阶段函数。结束后再次重启并恢复相同终局，退出凭证后再次重启，确认旧凭证不能重新连接。

游戏规则、随机牌序、暗牌及成员映射由服务器管理；大厅消息不能提交牌序或任意局面。脚本内的用户／选择是验收夹具。下一步接完整回合操作与2.5D场景，再接真实账户验证和部署。本批浏览器点击／截图／视觉验收被环境安全策略阻止，尚未完成，HTTP和网络自动检查另行验证。
