# 本地运行与验收

目前可以在本地跑通**服务端大厅到八回合终局的自动验收**。React大厅／棋盘界面尚未实现，当前命令会启动多个测试客户端并自动执行指定合法选择，不是人工点击游玩的页面。

## 环境与命令

需要Node.js >=22.12.0、npm >=10。在仓库根目录执行：

```bash
npm ci
npm run verify
npm run check:lobbies
```

已经按锁文件安装过依赖时可以省略npm ci。verify执行严格类型检查、全部Vitest测试和规则／服务两包构建。check:lobbies再从编译包运行端到端验收；根据电脑速度可能需要数分钟，最后应出现一行包含`"check":"PASS"`和`"viaLobbies":true`的JSON。

这个本地命令自动使用临时PGlite文件数据库，只监听127.0.0.1随机端口，无需配置数据库、域名、服务器或Docker。测试结束关闭客户端／Nest／数据库并删除本次临时数据；运行中中断则可以重新执行一次独立验收。它不改已有对局或连接真实服务器。

PGlite仅为测试用WASM PostgreSQL，生产服务仍按原方案使用原生PostgreSQL。原生数据库网络、跨进程竞争及部署属于后续验收，本命令不能代替它们。

## 本地覆盖的路径

可信测试服务为不同用户签发会话，客户端经真实loopback Socket.IO完成建房、邀请加入、配置先手／顺时针、本人准备、房主开始。房间满员并全部准备后，先关闭并重开应用及本地文件数据库，确认成员／配置／准备状态恢复，再开始同一个对局。

二人、三人、四人各实际进行八回合，保留采集方案、雷蛇本人清理和正式终局计分；中间阶段由服务端原有调度器推进，检查脚本不手动调用阶段函数。结束后再次重启并恢复相同终局，退出凭证后再次重启，确认旧凭证不能重新连接。

游戏规则、随机牌序、暗牌及成员映射由服务器管理；大厅消息不能提交牌序或任意局面。脚本内的用户／选择是验收夹具，不是账户注册／登录功能。下一步可在这组接口上实现本地可点击的大厅与游戏界面，之后再接真实账户验证和服务器部署。

大厅协议见[Lobby-Flow](Lobby-Flow-2026-10-27.md)，实际输出与限制见[大厅验证记录](testing/lobbies-validation-2026-10-27.md)。
