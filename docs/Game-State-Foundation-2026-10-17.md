# 最小对局状态、资源余额与标记守恒

日期：2026-10-17。状态：基础代码已实现，真实验证记录见 `testing/game-state-validation-2026-10-17.md`。这不是完整的游戏状态机。

## 已核对的规则事实

- 基础规则书印刷 p03：玩家选择红、蓝、绿、黄之一，每人有 30 枚对应颜色的玩家标记；取 1 枚放到计分轨道 0 分处；资源计数器从 0 开始。
- p04：决定起始玩家、决定初始资源点并结算绿色事件，然后获取初始资金。因此构造器定位在这些入场步骤之前，不提前发放金券、决定先手或替玩家选择资源点。
- p02：三人使用独立三人地图，准备事件牌时移除带四人标识的牌；p23 两人附录以三人规则为基础且未改这一条。两人复用三人地图，但依然使用独立人数规则 ID。
- p04–05/p13：资源与金券、至纯源石，以及分数分别记录。金券/至纯源石实体不足时可替代，玩家标记数量则有限；不能将 35 个至纯源石配件数误当成玩家资产上限。
- p05 和已批准 Board 模型：棋盘影响力槽保存玩家标记占用；不得再维护另一份能独立修改的标记位置。

## 当前实现

`packages/game-core/src/game` 对外提供：

- `createPreEntryGame(gameId, players)`：返回冻结的 `{definition, state}`；支持 2/3/4 人、唯一玩家 ID 与颜色。输入顺序只是稳定的座位/工程标记编号，不代表已经决定先手或发牌顺序。
- `GameDefinition`：固定对局 ID、玩家/颜色、人数规则 ID、地图定义引用、已确认事件目录引用，以及每人 30 枚标记的库存定义。标记 ID 在对局内有效，不是实体配件上的官方编号。
- `GameState`：状态版本、入场阶段、原有 BoardState、玩家资源余额/分数/计分标记引用，以及各自供应堆中标记 ID。原 1.0.0 是入场前基础结构；后续 1.1.0 增加入场进度，1.2.0 增加独立授权的探索进度，1.3.0 增加城市移动及双向切换；仍不代表完整回合、其他一般行动或结束阶段。
- `validateGameDefinition` / `parseGameDefinition`：验证人数、颜色、版本引用、库存唯一性、归属及每人恰好 30 枚标记。
- `validateGameState` / `parseGameState`：检查精确玩家覆盖、地图结构/引用、余额、标记归属与守恒、事件资源标记引用/颜色/资源/采集量和人数标识。
- `getMarkerLedger`：从已验证状态推导只读账本；不把该视图再写入 GameState。注入额外 `markerLedger` 字段会被 strict Schema 拒绝。
- `canAffordResources`：只计算五类资源是否足够，正确累计同种资源的重复成本，不修改余额，也不授权任何行动。

每名玩家初始：资源和金券等五项余额均为 0，分数为 0；**1 枚计分标记 + 29 枚供应堆标记 = 30 枚**。城市尚未入场，资源点尚未探索。

## 单一位置事实与守恒检查

| 数据 | 是否保存 | 含义 |
| --- | --- | --- |
| GameDefinition.markerDefinitions | 是，静态 | 每枚标记属于谁；不保存位置 |
| GameState.markerSupplyByPlayer | 是，动态 | 当前仍在玩家供应堆的标记 |
| GameState.players 的 scoreMarkerId | 是，动态引用 | 计分轨道上的那一枚；分数本身是轨道位置 |
| BoardState.influenceBySlot | 是，沿用既有权威字段 | 棋盘槽位的标记占用 |
| getMarkerLedger 的 location | 否，只返回推导视图 | 从以上位置事实计算，不维护第二份权威位置 |

验证器对每枚已注册标记检查：必须出现在上述当前支持位置之一且仅出现一次，位置所声明玩家必须等于库存所有者。既检查总数，也检查每个具体 ID；30 枚总数相同但串用其他玩家标记仍会失败。

当前只有供应、计分及棋盘三个位置种类。城市样式的宣告/使用标记需要其牌数据和状态模块，尚未纳入这个入场基础模块；不能用本模块校验已经包含样式使用的完整中局存档。

## BoardState 的兼容性补全

已确认的基础红牌 R01/R03/R04 会产生至纯源石资源标记。旧 `RevealedResourceMarker.resourceKind` 与对应 Schema 只有三种普通资源，无法表示这些已确认事实。本次为其追加 `pure-originium`，由对局验证器逐项对照事件目录检查种类及数量。

这是对已确认基础版数据的兼容性补全，没有改变地图拓扑、地图定义字段、两图内容摘要或 ADR-0001。不能根据字符串自行创建不存在的事件标记，同一事件资源标记也不能放在两个资源点。

## 验证能力的边界

解析器验证副本并深度冻结，调用者输入不被修改。`validateGameState` 验证数据结构、引用与库存，不验证此前发生的全部合法行动，也不验证余额变化是否来自真实奖励。

GameDefinition 必须来自服务器持有的可信对局配置；不能让客户端连同快照一起提交一个自定义 GameDefinition。状态校验成功不是接收客户端整份状态的授权。当前没有网络写入口或客户端权威状态提交接口。

后续 [入场模块](Entry-Flow-2026-10-18.md) 已实现绿色抽牌、初始城市/事件选择与资金发放，并加入预期版本检查。仍未实现跨进程并发控制、持久化幂等或数据库事务；城市样式标记用途、角色、完整回合及一般行动执行仍待完成。
