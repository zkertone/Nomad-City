# 雷蛇策略、替换与收尾选择 · 2026-10-23

## 已设计与规则依据

实际复读用户规则书20230803印刷p10、p13、p14和雷蛇原卡。PDF摘要实测 `6b87c026e317606de2324276ff117480b8e104f5b925a21d43b95af176ddbf42`。

- p14雷蛇策略：依次放置2个影响力，本回合收尾阶段移除1个自己的影响力；说明明确可选任意自己的影响力，不要求属于本次新放的两个。
- p14计谋：可选择支付3金券，替换1个影响力。替换定义是先移除，再在同一槽尝试放置自己的影响力；位于对手城市资源点的目标仍可移除，但不能放置自己的影响力。
- p13按顺序、尽量执行：能执行的非条件操作不能主动丢弃；无法放置时继续后续效果。条件费用可明确放弃，支付后才执行后续。
- p10采集结束后结算收尾效果，再传起始玩家、推进回合。默认按起始玩家开始顺时针处理；当前每名玩家最多有一个已支持的雷蛇收尾效果，未推断其他延迟效果顺序。

本轮实现雷蛇两种完整模式，当前基础角色为**7/10种策略/计谋模式**，尚缺极境、德克萨斯、坎诺特计谋。没有加入企业/感染者或虚构设施效果。

## 已实现：策略的两次尝试

`strategyChoice={kind:'liskarm-place',slotIds:[...]}`，数组最多2项。服务器按顺序重新查询每次放置的合法空槽与本人供应标记：

- 可以执行就必须给合法目标，不能只放1次而省略仍可执行的第2次。
- 第一枚用尽供应或填满最后合法空槽时，第2次自动跳过；两次都不可能时允许空数组。
- 未探索资源点、对手城市资源点、占用槽、重复目标以及不可执行时额外提交的目标都拒绝。
- 航道仍是独立对象，包含红区的航道不因此加设资源点探索限制；计分标记不属于棋盘影响力。

即使本次一次也无法放置，策略仍登记本回合收尾移除义务。因为收尾选择针对当时任意一个自己的影响力，不能预先绑定新标记ID、初始槽位，或在角色使用时因暂时没有影响力而过早取消义务。

## 已实现：计谋不是整块交换

`schemeChoice={kind:'liskarm-replace',costDecision:'pay'|'decline',slotId?:...}`。

选择decline时没有目标和费用；选择pay时先确认能支付3金券，且有影响力可移除时必须给目标。若棋盘没有影响力，支付后的替换步骤无法执行，按尽量执行跳过，不捏造成功目标。

选择任意现有棋盘影响力后：

1. 原标记回到其所有者供应堆，目标槽清空。
2. 再检查同槽能否放置自己标记，包括本人的实际供应与资源点限制。
3. 能放则取自己的供应标记放入该槽；不能则保留仅移除结果，不能改放其他槽或创造标记。

原文替换定义没有限定目标所有者，沿用该定义支持已有本人或其他玩家影响力；对手城市资源点明确只移除。本人供应耗尽时移除对手标记不会产生自己的新标记；替换本人时先归还的标记可再次使用。全局每人30枚标记账本始终守恒，不交换或更改标记所有者。

起始玩家both仍按策略→计谋执行，成功只弃置一次角色、登记一次收尾义务。若后续支付或目标无效，整个使用回滚，包括前两次放置；放弃计谋费用不会取消已发动策略的收尾义务。计谋单独使用不产生策略移除义务。

## 显式收尾与玩家选择

```ts
import {
  openManagedCleanup, getRoleCleanupOptions,
  applyRoleCleanupCommand, finishManagedRound,
} from '@nomad-city-online/game-core/game';

// 可信阶段入口；state必须已经完成全部玩家的采集结算。
const cleanup = openManagedCleanup(state, definition, { expectedVersion: state.stateVersion });
const options = getRoleCleanupOptions(cleanup, definition, authenticatedPlayerId);

// 玩家从自己当前棋盘影响力中选择；options是查询，不替代身份与版本校验。
const resolved = applyRoleCleanupCommand(cleanup, definition, { authenticatedPlayerId }, {
  type: 'resolve-role-cleanup', gameId: cleanup.gameId,
  expectedVersion: cleanup.stateVersion, slotId: selectedSlotId,
});
// 多人待结算时先让后续玩家逐个选择；全部完成后才能调用。
const nextRound = finishManagedRound(resolved, definition, { expectedVersion: resolved.stateVersion });
```

阶段进入cleanup，phase回到round-control，保留原起始玩家/回合/角色使用与棋盘。按当前playerOrder选择下一位未结算玩家，`getRoundTurn`/局部公开视图返回其身份；只能本人选择任意**当前**棋盘影响力，动作中移动过的标记按新槽位选择，不绑定原来放置位置。

确实没有任何本人棋盘影响力时，进入cleanup自动标为完成，不强迫玩家给不存在的目标。有可执行目标时绝不自动代选；需要本人命令移除恰好一枚并归还本人供应，全局版本+1、cleanupResolved=true。重复旧命令、再移除第二枚、移除他人/空槽、错误玩家或覆盖完成字段均拒绝。

`finishManagedRound`只在所有可执行收尾义务完成后回收未用角色、传起始玩家和推进回合。存在待选择移除时直接报CLEANUP_PENDING；旧行动/采集窗口也不能绕过cleanup。若没有可执行义务（未用策略或最终已无本人影响力），可沿用原直接finish入口完成自动跳过。没有把无法执行的效果标成一次虚构移除。

当前只处理雷蛇的这一个延迟效果类型；其他角色/设施延迟效果仍无入口，不能通过伪造已完成记录跳过。该增量沿用单一权威状态与既有回合调度，Accepted ADR与核心技术栈不变。
