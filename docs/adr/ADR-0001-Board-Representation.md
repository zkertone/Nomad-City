# ADR-0001：地图定义、状态与航道关联模型

状态：**Accepted**

批准人：项目负责人朱镓铉；依据：Work 开发任务 002 明确批准 ADR-0001 并授权 v0.2.0 实现。

## 背景

用户已确定服务器权威、规则与视觉分离。规则书及两面实物地图显示：资源点和航道分别具有影响力槽；同一航道可能关联 3 或 4 个资源点。三人图有独立拓扑及容量变化，无法仅通过删除四人图 G 区生成。探索和采集按航道收费，城市移动按所选航道清除影响力。

## 已批准决策

1. 不可变 BoardDefinition 与对局 BoardState 分开；每次对局固定定义版本及摘要。
2. 航道作为独立对象，使用 incidentNodeIds 表示两个以上端点；路径计算使用资源点—航道关联图。
3. 两张地图面独立配置，两人规则复用三人几何、使用独立 RuleSet。
4. 槽位占用、指示物、城市位置各只保留一份权威状态。区块控制和邻接关系由服务器计算。
5. Three.js 坐标、模型、点击区域及动画属于独立展示数据，通过稳定 ID 关联领域对象。

## 取舍

- 普通双端边表示简洁，但需要拆分分叉航道，会造成影响力槽重复、路费重复或清除范围错误；不采用这一未经额外约束的表示。
- 格子地图与空间距离不能表达本项目原始规则；不采用。
- 将地图状态放进 Three.js 对象会使存档、验证、重连及测试依赖渲染；与用户已定原则不符。
- 关联图稍多一种对象类型，但直接保留实体地图中的共享航道身份。
