# ADR-0002：共享对局的2D与2.5D显示模式

日期：2026-10-27（Asia/Shanghai）  
状态：**Accepted**  
批准人：项目负责人朱镓铉。依据：负责人提出“两套界面，一套简化纯2D，另一套有建模”；在说明“简化2D＋2.5D混合版、共享状态和规则、每位玩家独立选择模式、先完成2D操作闭环”的方案后，明确回复“我觉得很可以”。  
实施状态：**共享展示契约及现有2D资源点概览已接入；2.5D模型、镜头和模式切换尚未实现。**

## 决定

| 显示模式 | 表现 | 实现阶段 |
| --- | --- | --- |
| 简化2D | 平面棋盘、建筑图标／插画及轻量动画，优先操作清晰与完整玩法 | 先完成；当前仅资源点概览及首批操作 |
| 2.5D混合 | 保留平面棋盘布局，配Blender立体建筑、Three.js／R3F渲染、光影、受控镜头和动效 | 2D操作闭环后接入，承接此前C路线 |

2.5D是项目呈现名称，底层仍是3D渲染。本次没有批准将整个地图／地形／环境重做为完整3D场景，也没有修改地图拓扑、行动距离或任何游戏规则。

两种模式共享React大厅、玩家面板、事件／角色／采集选择、Socket.IO会话与请求控制器，以及唯一服务器权威GameState。显示模式是玩家本地偏好，不进入GameState、房间规则配置或数据库CAS，不影响其他玩家。未来同一局允许不同玩家选择不同模式；当前尚无2.5D可用组件，因此不展示可操作的2.5D切换开关。

## 展示边界

- BoardPresentationProps只接收公开＋本人私有GamePlayerView、静态BoardDefinition、服务器候选ID、本地选中项及交互回调，不接收原始权威快照或暗牌堆。
- BoardIntent使用稳定nodeId／routeId／slotId表达选择；当前2D实现资源点选择，路线／槽位意图为后续共同接口，尚未实现的交互不宣称可用。
- 布局、坐标、模型、材质、相机、动画归各渲染器；确认操作由共享控制器提交原玩家通道，服务器校验并保存后返回本人视图。动画结束不能改变回合或产生额外操作。
- 模式切换将使用同一已保存版本和同一候选，不重新开局、不重洗牌、不改变私有信息权限。可用性、WebGL失败降级和本地偏好持久化在2.5D接入时验证，当前未实现。

## 当前实现与后续

独立renderers/types.ts、Board2D.tsx、BoardRenderer.tsx保留现有资源点概览行为，仅2D在已实现注册表中。角色／供应设施等操作面板留在共享React界面外层，两种棋盘模式都使用同一面板及请求合同。未引入Three.js或模型依赖，未用平面资源点分组冒充实体棋盘完整几何。

先接回合准备／主要行动／采集／清理／终局，形成完整可点击2D闭环，再按已定工业风补准确地图展示及2.5D建筑资产。该顺序不表示当前页面已人工验收；此前云浏览器安全策略拒绝仍是验证限制，后续不得绕过或把HTTP测试记作点击通过。

本决策补充而不替代[ADR-0001](ADR-0001-Board-Representation.md)。服务端规则、资料摘要、GameDefinition／GameState、旧存档与基础／企业／企业家版本边界保持原义。
