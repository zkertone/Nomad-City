# 同时采集阶段 · 2026-10-18

## 依据与范围

基础规则书《游城拓荒铸基者-规则书20230803.pdf》印刷 p09–10：两轮玩家行动之后，全体玩家同时采集。每人选择任意数量的本人城市/影响力所在资源点，以航道连接到当前城市；路费与探索相同，同一航道在本人本次采集中只计费一次。不能用本阶段获得的金券支付路费。每个点只采集一次，按资源标记实际种类及数量获得资源，不按影响力枚数翻倍。p06 提供航道收费依据。已视觉核对，不加入扩展规则。

**不是所有红色资源标记都产出 2**：既有已核验目录中 R05/R06 固源岩 ×2，其余红牌按各自标记 ×1。生产代码读取 resourceMarkerByNode 中已验证的 resourceKind/harvestAmount，不从颜色推导收益。

本模块仅实现采集选择、连通校验、收费与收益；不实现收尾、角色效果、完整回合调度或建设。尚无客户端提交整份权威状态的入口。

## 可信入口和玩家请求

`openHarvestPhase(state, definition, {roundNumber, expectedVersion, deckOrder?})` 是可信编排入口，没有单个 actorId。调用方必须先确认两轮行动结束。现有核心尚未具备角色盖放、顺时针轮转和主要行动额度，因此本入口不能证明完整回合时机。仅前一已实现阶段 complete 才可开启；直接从完成入场进入时可初始化精确牌堆，其余情况不允许重置牌堆或回合倒退。

`getHarvestEligibleNodeIds` 提供本人已揭示城市/影响力点；`getHarvestQuote` 返回只读的费用分项、支付对象与资源收益，输入不变。玩家适配器提供 authenticatedPlayerId，不能由请求指定玩家、阶段、金额、收益或牌堆。

```typescript
const next = applyHarvestCommand(state, definition, { authenticatedPlayerId }, {
  type: 'set-harvest-plan', gameId: state.gameId, expectedVersion: state.stateVersion,
  plan: {
    nodeIds: ['D-01', 'D-03'],
    routeIds: ['R-route-01', 'D-route-01'],
    // 多个对手在同一收费航道时，必须选择其中一个实际所有者：
    // tollRecipients: [{ routeId: 'D-route-01', payeePlayerId: 'p2' }],
  },
});
```

示例仅展示格式，实际目标必须具备本人城市/影响力、实际揭示资源及连通关系。空计划 `{nodeIds: [], routeIds: []}` 表示不采集。每位玩家在所有计划齐备前可以替换本人计划；不修改其他玩家方案。

## 网络与收费

- plan 只保存目标点、所选航道及必要收款方。目标重复拒绝；航道按独立身份去重收费，不把三/四端航道拆成多条收费边。
- 所选网络的全部目标和航道必须通过资源点–航道关联图与实际当前城市相连；列表顺序不影响连通性。允许经过未探索中间点；不以显示坐标或最短路决定权限。
- 没有目标时不允许附带航道；未知引用和不连通支路拒绝。连通的额外航道仍按玩家选择计费，不自动替玩家删改方案。
- 本人航道影响力优先免费；无本人、只有对手时支付 2 金券给一个实际所有者；仅一位可默认，多位必须明确选择；无人影响力时向供应支付 2。
- 免费/供应航道不能指定玩家收款；未选航道、非所有者、重复收款指令均拒绝。探索与采集复用内部 route-tolls.ts；拓扑工具不负责经济决策。
- 不同玩家各自支付连接网络的费用，共享航道去重只发生在本人方案内。

## 同时结算与状态

GameState **1.5.0** 增加 `phase: 'harvest'` 和唯一 `harvest: {roundNumber, status, plansByPlayer}`。plansByPlayer 必须恰好包含全部真实玩家。planning 至少一人未提交；最后一份方案到达后自动 complete。未额外持久化余额、预计算费用或收益账本。

规划期间全部库存、资源标记、城市、牌堆和余额保持不变。最后一份请求在同一旧局面上重新计算全部方案并检查每人的支付能力，先扣所有人的费用，再付收款方和资源收益。不允许依赖同阶段尚未到手的路费收入来支付连接费用。这保证纯函数结果不依赖玩家提交顺序。任一余额/版本溢出或选择无效则整次请求拒绝，不留下部分扣款或收益；已有方案仍可替换。

每个成功提交/替换请求仅增加一次全局 stateVersion；过期请求拒绝，适配器需读取新版本后重试。完成后不接受重复采集；采集完成后的下一阶段只能使用更晚回合。实际收尾和下一回合授权依然由未来回合编排实现，入口不自动跳转。现有探索、城市移动、部署/调度在后续回合保留 1.5.0、唯一局面、牌堆和玩家顺序；兼容既有 1.0.0–1.4.0，不静默迁移。

快照校验只证明当前结构与跨对象一致性，不证明历史发生过。complete 方案不再按结算后余额检查旧支付能力，以免合法扣款后的恢复失败。网络接入时还需要公开投影、方案可见性策略、认证和数据库事务/CAS，不能直接公开整份含隐藏牌堆的状态。
