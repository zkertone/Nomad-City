## 客户端与边界

测试以可控传输复现：push高版本先到、旧ack后到不回退；选房期间旧订阅ack不覆盖新房；只接纳当前roomId／lobbyId；会话失效清私人视图／邀请／标签页凭证和选择，旧会话迟到结果不能恢复数据；断线清视图，重连重新认证并订阅；完整分页按服务端游标；超时写入不自动重发、不展示候选视图；固定错误不显示原SQL文字；退出确认丢失仍清本地凭证。

首轮全量之后，代码复核发现unavailable事件未过滤已切换的房间，可能清掉新页面。增加明确房间／大厅ID校验和1项同时覆盖旧通知／当前通知的回归，最终2485项通过。没有放宽原断言或减少测试。

新增两个真实Socket.IO用例：当前入场操作者取得原核心合法起点，其他人options=null，非成员／缺失房间一致不可见；身份注入拒绝且读取不改状态；实际选择节点后只返回当前已揭示事件原文／奖励，不泄漏牌序。受管回合无入场操作，存储故障安全归一。网络文件现69项，原67项均保留。

## 编译后本地主机检查

check-local-web使用独立临时PGlite文件库及127.0.0.1随机端口，不读取dev:local保留数据，也不连接真实服务器。GET页面和两个编译资产成功；浏览器JS／CSS无node:crypto、Nest或PGlite运行时。公开地图目录仍18／22资源点；package.json等非静态路径404。

本地fixture入口要求匹配Origin的JSON POST，仅接受fixtureId1–4：错误来源／GET拒绝、0／5／附加userId／null拒绝；普通生产createRoomSocketApplication同路径404。凭证原文只在内存用于测试，不打印到原始日志，数据库仍只保存会话摘要。

2／3／4个实际客户端从本地HTTP测试身份开始，真实Socket.IO建房／加入／配置／本人准备／开始；选项均从room:entry-options取得，循环由当前有权玩家显式选择合法节点、绿色事件及两人奖励放弃。共19次真实玩家写入触发30次自动初始化，到原1.16.0第一回合；不调用阶段函数或注入布局／轮次／余额。关闭并重开本地主机及PGlite文件库，原凭证恢复三场相同本人视图与版本。

这3场只验证入场到第一回合，不是又3场八回合；完整八回合的既有独立脚本本批未逐一重跑，所有原单元／网络测试在2485项全量中执行。用户可继续npm run check:lobbies独立复现八回合。

## 过程修正与验证限制

首次TSX多余右括号导致strict和构建报错，修正后检查通过，未改规则。首次HTTP检查403：随机端口主机测试中Host使用监听后的真实端口，而本地主机校验仍用配置端口0；改用请求socket.localPort校验回环Host，Origin约束保持，最终编译检查通过。首次失败日志保留。

受管理预览最初未就绪，开发启动器补充标准--port支持后启动；其代理要求的--host参数仅在受管理QA环境使用，普通本地运行仍绑定127.0.0.1。明确预览Origin配置放在忽略目录，未放宽默认服务认证。最终云浏览器对预览导航返回安全策略拒绝，按工具要求停止浏览器尝试，没有换浏览器、代理、原始CDP或其他方法绕过。因此没有截图，也没有宣称两窗口实际点击、移动端布局或视觉完成验收。
