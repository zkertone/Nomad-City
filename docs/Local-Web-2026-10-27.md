## 本地启动

仓库根目录需要Node.js >=22.12.0、npm >=10：

```bash
npm ci
npm run dev:local
```

等待构建完成并打印本地地址后，打开`http://127.0.0.1:5173`。在不同浏览器窗口或标签页选择不同测试用户；创建2／3／4人大厅，分享大厅编号和邀请凭证，加入满员后由房主明确先手与顺时针顺序，各人准备，开始并进入对局。

按当前玩家提示选择可用起点、B-01奖励（适用时）、已揭示绿色事件选项，以及两人额外影响力放置／放弃；其余玩家等待。全部入场完成后，服务器自动初始化到原1.16.0第一回合，当前页面显示局面和余额；本批还不能通过页面操作角色／主要行动／采集等完整回合，不宣称网页已可玩完整八回合。

Ctrl+C停止服务；`.local/database`保留测试对局及会话摘要，重新启动可恢复同一状态。`.local/`全部忽略，不提交测试数据库、凭证明文或预览设置。默认只绑定127.0.0.1，无需服务器、域名或Docker；自动化验收仍用各自临时目录并清理。

端口可通过`PORT`或启动器`--port`参数设置，Origin应与实际打开地址一致，默认即上述127地址；受管理的内部预览单独使用明确Origin配置及其启动参数，普通本地运行保持回环地址。没有创建或部署Sites站点，也没有连接用户服务器。

## 页面与可见性

- 独立packages/web使用React19.3.1、react-dom19.3.1及原socket.io-client4.8.4；Vite8.3.5构建，浏览器侧严格tsc独立执行，类型导入在构建时擦除。
- 大厅支持创建、邀请复制（剪贴板不可用时显示当前房主凭证供手动复制）、加入、列表完整分页、选择／恢复、配置／反向座次、准备／取消准备、开始、成员离开／房主取消，以及新邀请旋转。
- 房间页面按已验证BoardDefinition分区列出资源点，不伪造原版地图几何或增加航道规则。服务器提供合法入场候选及已揭示事件文本／奖励，前端展示选择；余额和玩家分数只读。
- 私人非商业标记、基础版边界、本地测试身份及未接入回合页面的范围明确展示。视觉延续原创工业风方向，当前采用代码绘制城邦插画和资源点概览，非最终2.5D场景。
- 依赖只在前端／开发构建范围新增；已有Vite8.3.4升级至8.3.5，关联rolldown1.2.13→1.2.15及oxc类型跟随锁定。其余旧包version／resolved／integrity核对不变，未升级规则或服务运行库。Prettier仅临时执行格式化，不成为项目依赖。

## 会话与客户端确认

本地开发启动器使用测试PGlite文件数据库，单独安装`/__local/session`、`/__local/catalog`和构建后静态资源路由。只有严格的fixtureId1–4可以签发对应固定local-user身份，不接受任意userId；请求需匹配明确Origin及JSON方法，Host限定当前服务和配置地址，正文大小受限。凭证不写日志或URL，数据库只保留原SHA-256摘要。

这些路由仅存在scripts/local-app.mjs开发工具；生产RoomSocketModule默认不安装，普通createRoomSocketApplication无fixture入口。新增configureHttp只供可信主机在init前挂载HTTP路由，没有客户端开关。测试选择器不能作为公开账号登录方案，也不能部署到生产代替真实认证。

浏览器sessionStorage按标签页保存会话及选中的大厅／对局ID；不保存游戏快照或邀请明文。邀请只在当前房主内存中，断线／切换／失效清除。断线先清本人视图和邀请，重连重新验证并订阅已保存状态；失效／退出清凭证、选择和个人数据，其他用户的后到响应不能恢复旧身份视图。

客户端只接纳当前选择房间／大厅的消息，保留较高状态版本，较晚旧ack不能覆盖新push。游戏下一请求使用最新GamePlayerView版本，不使用可能较低的玩家写入receipt。候选选项只有gameId／roomId／stateVersion都匹配时才展示；超时不自动重发写入，也不使用Socket.IO离线队列继续操作，需刷新确认实际结果。

## 入场选项接口

新增严格`room:entry-options {roomId}`，沿用会话与成员验证；读取后再次认证，不触发自动阶段或增加GameState版本。成功返回ready／roomId／gameId／stateVersion，以及只有当前入场操作者才有的options。非操作者或入场后options=null，非成员／不存在统一ROOM_UNAVAILABLE。

选项复用核心getLegalInitialNodeIds、getLegalEntryInfluenceSlotIds和已揭示事件目录；事件只含当前牌名／原文／选项及效果，不发未揭示牌堆、成员账户或完整存档。实际选择仍由原13通道entry执行，服务器再次校验版本／操作者／合法性。没有复制规则引擎到浏览器，旧视图和存档含义不变。

技术参考：[React createRoot](https://react.dev/reference/react-dom/client/createRoot)、[Vite TypeScript／TSX](https://vite.dev/guide/features.html)。Vite转译不代替tsc，项目verify同时执行原服务／规则和新前端严格检查。
