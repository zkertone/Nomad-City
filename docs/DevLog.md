项目负责人在确认文本、数值后表示“不用我下指令”，要求按既定下一步持续推进。本次先核对规则书结算边界，并将已确认资料实现为独立 TypeScript 静态目录；不实现完整事件/经济/行动结算，不改技术栈或 Accepted ADR-0001，不发布新版本。开发前读取固定提交 `e29b00ee6285515e8a432ed18938bd07193598b7` 的全部最新仓库文件。

### 已设计

- 事件资料与 BoardDefinition/BoardState 保持独立，按已确认牌索引关联叙事和效果。
- 效果区分本人/每名对手收益、条件成本和三种影响力放置范围；只描述数据，不自动执行。
- 事件哈希使用新命名的规范化协议，保留选项与效果数组顺序，不改变原地图协议。
- 已对照基础规则书 p04–07、p12–13 核对顺序、尽量执行、条件式费用及缺少标记；记录原文约束与后续行为测试要点。

### 已实现

- `packages/game-core/src/events`：22 张基础牌、49 个选项的 JSON 静态目录、完整背景/对白、资源图标、人数标识、费用及效果。
- Zod 严格 Schema、完整基础 ID 集合、牌色/ID 对应、选项归属/顺序、数值和范围检查；解析副本嵌套只读并冻结。
- 固定源文档 SHA-256、确认日期与来源提交；固定内容摘要验证，重算坏数据的摘要也不能通过批准基准校验。
- 按 ID/颜色的只读查询、根包与 `/events` 导出、编译加载检查脚本；README、结算边界说明及本次测试记录。
- 两份用户确认文档、原地图所有代码/测试/清单、ADR、依赖版本和锁文件保持原字节；企业扩展没有混入。

### 已测试

- 缓存不足导致离线 npm ci 失败；按原锁文件在线安装 42 个包成功。
- 初始模块 typecheck 成功；增加测试后首次 verify 因测试参数类型及反向数据构造类型错误退出 2，尚未运行 Vitest；修正测试代码后重新执行通过。
- 最终 `npm run verify` 退出 0：strict 类型检查、**225/225 Vitest 测试**（原地图 88 + 新事件 137）、构建全部通过。
- `npm run check:events` 退出 0：实际编译模块、子路径及根导出加载通过。
- `node scripts/check-maps.mjs` 通过，原两图内容摘要未变。
- 每张牌文案与每个选项效果直接对照确认 Markdown，覆盖正向和反向、重算摘要篡改、冻结与输入不变；详细命令和限度见 `testing/event-catalog-validation-2026-10-17.md`。

### 待完成

最小 GameState、玩家资源及 30 枚全局标记账本、事件选择/待结算阶段和各项行为验证，随后再衔接探索/城市移动等具体行动。静态目录通过测试不代表能实际结算事件。角色、城市样式、UI、联机与部署仍未完成；本次没有推进扩展或对外部署。

## 2026-10-17 · 最小对局状态、资源与标记守恒

### 需求与依据

项目负责人要求“不需要我参与的就不用暂停”，延续按既定目标自主推进的授权。本次实现前读取最新仓库 `dc4c17e04ea715bb519cd02470116c7dc74cac04` 的 DevLog、ADR 与实际源码，核对基础规则书 p03–05、p13、两人附录 p23；没有自行补充规则或改变 Accepted ADR-0001。

### 已设计

- GameDefinition 保存固定玩家/颜色、定义引用和库存所有者；GameState 组合现有 BoardState，保存余额、分数、计分标记引用与供应堆。
- 账本由实际位置事实推导，避免复制 BoardState 槽位占用为第二套权威位置。
- 构造器定位在入场选择之前：每人 30 枚中 1 枚已放计分 0 点，供应为 29 枚；初始资金必须等官方后续步骤，不提前发放。
- 人数规则独立于地图；两人/三人使用三人地图但规则 ID 各自独立。没有推断先手或替玩家选资源点。

### 已实现

- `packages/game-core/src/game`：类型、严格 Schema、GameDefinition/GameState 构造和校验、守恒与归属校验、冻结推导账本、资源费用查询及公共包导出。
- 资源余额支持源岩、源石、异铁、金券、至纯源石；分数单独保存。重复资源成本累计后判断，整数边界安全，查询不改余额。
- 对资源指示物与确认事件目录逐项比对种类、采集量、颜色、人数标识和唯一占用；补全旧 BoardState 遗漏的至纯源石类型/Schema。
- `scripts/check-game.mjs`、说明文档、真实测试记录、README 与交付清单更新。
- 既有地图数据/摘要、已确认事件文档/目录、ADR 与依赖保持不变，没有 UI、网络写状态入口或部署。

### 已测试

- 初始模块 `npm run typecheck` 退出 0；加入测试后的首次 `npm run verify` 退出 0：**311/311 测试**（地图 88、事件 137、状态 86）、strict 检查和构建通过。
- `npm run check:game` 退出 0，编译后的根导出及 `/game` 子路径可实际初始化 2/3/4 人。
- 原 `node scripts/check-maps.mjs` 与 `node scripts/check-events.mjs` 均退出 0，摘要和加载检查通过。
- 全部 22 个资源指示物与 BoardState 兼容；反向用例覆盖标记重复/丢失/串用、错误引用、玩家集合、资源数值、阶段、人数牌及重复成本。
- 本轮没有失败测试；实际范围与限制见 `testing/game-state-validation-2026-10-17.md`。

### 待完成

入场先手/资源点/事件选择和资金发放的服务器流程，以及待结算事件、完整回合和行动验证。城市样式的宣告/使用位置还未纳入当前入场账本，角色和样式卡数据仍未齐备；不能用这一模块代表完整中局状态。状态校验不验证历史行动来源，不允许以“校验通过”为由接受客户端自定义余额或 GameDefinition。
